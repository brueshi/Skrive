# Skrive Design System

The visual and behavioral language of Skrive. This document captures the brief, the principles that fall out of it, and the concrete tokens that implement them.

This is a **living document**. Color values, type choices, and motion curves listed below are starting points — tuned over time as we draw icons, prototype layouts, and live with the result. When something changes, update it here.

For the icon inventory and drawing checklist, see [`icon-inventory.md`](icon-inventory.md).

---

## The brief

Skrive is a writing tool with the soul of a hand-built object. The reference points are mid-century Danish furniture and the interior of a restored Aston Martin — both share the same idea: every control was placed by someone who cared, every material was chosen, every detail has a reason. Skrive belongs in the same conceptual space as a Wegner Wishbone chair, a Smiths gauge, a Hermes 3000 typewriter, a Bang & Olufsen Beomaster.

The four words that hold this together:

> **Tactile. Mechanical. Deliberate. Warm.**

These are the test. Any design choice that doesn't satisfy at least three of the four should be reconsidered. A choice that satisfies all four is probably right.

The constraint that holds the brief honest:

> **No inspiration from other apps.** References come from real-world objects, printed matter, and the work of designers and craftspeople — never from other software, regardless of its quality. Borrowed personality reads as borrowed.

## Principles

These are the testable rules that fall out of the brief. When a design decision is unclear, run it past these.

### 1. Made object, not screen

Every element should feel placed by a person, not generated by a template. If a choice could have been made by any UI library, it's the wrong choice. The whole product should feel like it was *designed*, not *configured*.

### 2. Form follows function. Form has soul.

No decoration. But the absence of decoration is itself warmth — because every element that *is* there was chosen rather than defaulted. Restraint is generous when the restraint is deliberate.

### 3. Borders, not shadows

Elevation is communicated by 1px hairlines in the rule color. Never by drop shadows, blurs, or glows. Shadows are for screens; borders are for objects. Joinery, not glassmorphism.

### 4. Hard corners on panels, soft on inputs

Sidebars, headers, dividers, and panels meet at clean lines — like the joinery in a Wegner cabinet. Buttons, inputs, and tooltips have a small radius (2–4px), the way a milled aluminum knob has a barely-perceptible chamfer at its edge. Never overtly rounded.

### 5. Color is meaning, never decoration

A color appears in the UI only when it carries information: a link, a focus ring, a save indicator, a warning. Everything else is paper, ink, and wood. The accent color is the brass switch on the Beomaster — present, important, used once.

### 6. The empty space is part of the object

Generous breathing room everywhere. Sidebar items get more padding than feels efficient. Headers get more height than competing apps would use. The empty space is a feature, not unused capacity. Scandinavian interiors are spacious; Skrive should be too.

### 7. Mechanical motion, not springy

Things move with weight. A drawer opens with friction and stops decisively. A switch clicks. A gauge needle settles — it doesn't oscillate. No bounces, no overshoot you can see, no spring physics. Damped. Considered.

### 8. The bench is real

When stuck, look at real objects — not other software, no matter how good. Pull from the bench (below) and your own additions to it.

## Typography

Three faces, three jobs.

| Face | Use | Stack |
|---|---|---|
| **Serif** | Editor body — the writing itself | `"Iowan Old Style", "Palatino Linotype", "Palatino", "Georgia", ui-serif, serif` |
| **Sans** | UI chrome — sidebar, header, buttons, menus | `-apple-system, BlinkMacSystemFont, "Inter", system-ui, sans-serif` |
| **Mono** | Code blocks, file paths, keyboard shortcuts | `ui-monospace, "JetBrains Mono", SFMono-Regular, Menlo, Consolas, monospace` |

The serif body type is doing most of the personality work. The system sans stack is acceptable for v0.1. Revisit at v0.5 if Skrive starts to feel generic — at that point, candidates worth experimenting with: a literary serif body face (Sabon, Plantin, Tiempos, Charter), a more deliberate UI sans (something with personality, not Helvetica).

### Type scale

A careful scale, not a Tailwind one. Anything outside this scale is wrong.

| Token | Size | Use |
|---|---|---|
| `--text-xs` | 12px | Micro labels, status, breadcrumbs |
| `--text-sm` | 13px | UI body — sidebar items, buttons, menus |
| `--text-base` | 15px | UI emphasized — selected file, current heading |
| `--text-md` | 17px | Editor body (the writing itself) |
| `--text-lg` | 20px | Section heads inside panels |
| `--text-xl` | 28px | Page heads — preferences, dialogs |
| `--text-display` | 44px | Display — welcome screen, empty states |

The 17px editor body anchors everything. UI text is *smaller* than the writing surface — the right hierarchy for a writing tool.

### Line height

| Token | Value | Use |
|---|---|---|
| `--leading-tight` | 1.3 | Display, large headings |
| `--leading-snug` | 1.5 | UI text, sidebar items |
| `--leading-relaxed` | 1.7 | Editor body |

## Spacing

A 4px base scale. Eight values total. Anything outside the scale is wrong.

| Token | Value | Use |
|---|---|---|
| `--space-1` | 4px | Tightest gaps — between an icon and its label |
| `--space-2` | 8px | Default small gap |
| `--space-3` | 12px | Internal padding inside small elements |
| `--space-4` | 16px | Internal padding inside panels |
| `--space-5` | 24px | Section spacing |
| `--space-6` | 32px | Generous internal margins |
| `--space-7` | 48px | Major separations |
| `--space-8` | 64px | Display-level breathing room |

### Component dimensions

Density is **spacious**, not compact. The user is writing — they don't need to see ten things at once.

| Element | Height | Notes |
|---|---|---|
| Header bar | 48px | More than competing apps would use |
| Sidebar item | 36px | Deliberate room |
| Button (primary) | 36px | Same as sidebar item — visual rhythm |
| Input field | 36px | Same |
| Tooltip | 28px | Smaller because they're transient |

### Sidebar width

Default `260px`. User-resizable, with a `200px` minimum and `400px` maximum. Resize state persists per project.

## Border radii

Three values. The world isn't more complicated than this.

| Token | Value | Use |
|---|---|---|
| `--radius-sm` | 2px | Tags, small chips |
| `--radius-md` | 4px | Buttons, input fields |
| `--radius-pill` | 9999px | The save dot, status indicators |

**Panels, sidebars, headers, and dividers have no radius.** They meet at hard corners. Joinery, not soft edges.

## Surface treatment

The thing that communicates "made object" most directly.

- **Borders, not shadows.** A 1px hairline in `--skrive-rule` is the entire elevation system. Sidebar / editor boundary, header / content boundary, top of every panel.
- **Hairline weights.** Always 1px. Never 2px borders. Never 0.5px borders that look fuzzy on non-Retina displays.
- **No glassmorphism.** No blurs. No translucency. No gradients beyond the imperceptible warmth of the base palette.
- **Selection states are tactile.** A selected file in the sidebar gets a subtle background tint and a 2px brass-colored marker on its left edge — like a key that's been pressed, or a brass plate next to a switch. Not a glow.
- **Focus rings are small and accent-colored.** A 2px outline in `--skrive-accent`, offset 2px from the element. Functional, not decorative.

## Motion

The Aston Martin reference matters most here. Mechanical motion has weight: a switch toggles, a needle settles, a knob detents. **No spring physics. No visible bounce. No overshoot.**

### Duration tokens

| Token | Value | Use |
|---|---|---|
| `--duration-snap` | 0ms | State that can't be in-between (file selection, mode switch result) |
| `--duration-switch` | 120ms | Binary toggles (sidebar toggle, mode toggle) |
| `--duration-settle` | 280ms | Layout changes (split view divider, panel slide) |
| `--duration-glide` | 480ms | Gentle entrances (focus rings, save indicator pulse) |

### Easing tokens

| Token | Value | Use |
|---|---|---|
| `--ease-mechanical` | `cubic-bezier(0.4, 0, 0.2, 1)` | Switches, toggles |
| `--ease-settle` | `cubic-bezier(0.2, 0.8, 0.2, 1)` | Layout transitions |
| `--ease-glide` | `cubic-bezier(0.32, 0.72, 0, 1)` | Slow gentle moves |

These are starting curves. We tune them by feel, not math. The test: does the motion feel like a mechanical part settling, or like a UI element animating?

### What we don't use

- `ease`, `ease-in`, `ease-out`, `ease-in-out` — too generic
- Spring physics with visible oscillation
- Bounce easings (the elastic / back family)
- Anything longer than 480ms for UI transitions
- Stagger animations that draw attention to themselves

## Iconography

The detailed icon checklist lives in [`icon-inventory.md`](icon-inventory.md). This section spec'es the *style*.

### Style brief

Icons should feel **drawn, not generated**. Like the indicator marks on a vintage Smiths gauge, the engravings on a Beomaster face plate, or the symbols in a draftsman's specification sheet. Geometric base — circles, rectangles, lines — but with the slight imperfection of being struck rather than computed.

The single test: *would this icon look at home engraved on the face plate of a Beomaster from 1972?* If yes, it's right.

### Technical parameters

| Parameter | Value | Notes |
|---|---|---|
| **Base grid** | 24×24 | Standard. All icons drawn at this size. |
| **Safe area** | 20×20 | 2px padding on all sides. Nothing critical touches the edge. |
| **Stroke weight** | 1.5px (start) | Tune by feel after drawing 3–5 icons. Acceptable range 1.25–1.75. |
| **Caps** | Round, small radius | Present but not announced. Not chunky. |
| **Joins** | Round | Never mitered. |
| **Color** | `currentColor` | No fills baked into the SVG. Inherits from parent text color via CSS. |
| **Format** | Inline SVG, one Svelte component per icon | Tree-shakable, color-flexible, no sprites or fonts. |
| **Small variant** | 16×16, hand-drawn separately | For the ~6 gutter icons. **Never** scaled from the 24×24 version. |

### Drawing principles

- **Geometric base, slight hand quality.** A circle is a circle. But it's a circle drawn carefully by a human, not computed by a vector tool.
- **Negative space matters.** Generous breathing room within the 24×24 grid. The empty space is part of the icon.
- **Partial fills, used sparingly.** A small filled wedge inside an otherwise outlined icon (like the pointer of a gauge) is acceptable when the filled element is what the icon is *about*. Most icons are pure outline.
- **No clever twists.** No icon has a "feature" that exists for its own sake. The job comes first.
- **Hand-tune at small sizes.** The 16×16 variants are independently drawn, not scaled. Strokes get fuzzy and details disappear when you scale down.

### The Skrive constant

The unifying device that runs through every icon. It's the small detail that makes the set feel like *one set* instead of 30 unrelated drawings. **You don't tell users it's there. They never consciously notice. But it's why the set feels coherent.**

This is **chosen by the designer** once 3–5 icons exist. Possibilities:

- A specific angle that appears in every chevron, fold, and pointer (e.g., 54°, not 60°)
- A specific proportion that governs every rectangular shape (e.g., 5:7, not 1:1 or 16:9)
- A specific small detail — every icon has one element exactly 1.5x the stroke width
- The way enclosed shapes (fold corners, indicator dots) always echo the outer shape's proportion

Once chosen, document it here and use it nowhere else in the design system. It belongs to the icons.

**Status:** to be chosen. Update this section when decided.

## Wordmark

The Skrive logo. Used in the header bar, the empty state, and (eventually) the landing page.

**Status:** undefined. Open question. Possibilities to explore in paper.design:

- A careful serif setting of "skrive" or "Skrive." in the body face or a dedicated display serif
- A custom letterform that draws from Northern European type traditions without being kitschy
- A pure mark — a single graphic element that suggests writing without a literal pen
- The wordmark as the only branded element, with no separate icon

Any wordmark choice should pass the four-adjective test: tactile, mechanical, deliberate, warm.

## How this document is maintained

This is a working spec, not a marketing document.

- **Anyone can edit it.** When you change a token in code, change it here too.
- **Mark changes inline.** When updating a value, leave the previous value in a comment for context. Example: `--skrive-bg: #f4efe6; /* was #f7f5f0 — too neutral */`
- **The principles section is more stable than the tokens.** Tokens drift; principles shouldn't.
- **When in doubt, run it past the four adjectives.** Tactile, mechanical, deliberate, warm. Three of four is the floor.

For updates that meaningfully change the visual direction, add a short note to the bottom of this document with a date and a one-line summary of what changed and why.
